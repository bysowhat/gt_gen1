# 01 — 整体流程与调度

本文档梳理从 shell 入口到子进程的整体执行流程、多 GPU 调度机制、子进程隔离、
超时/黑名单容错、以及断点续跑（幂等性）的实现。

---

## 1. 三个 shell 入口

| 脚本 | 调用 | 作用 |
|------|------|------|
| `run_gt_pose.sh` | `main_controller_sp_pose.py` | **只跑 Pose 阶段**（生成观测点） |
| `run_gt_traj.sh` | `main_controller_sp_traj.py` | **只跑 Traj 阶段**（生成观测轨迹） |
| `run_gt.sh` | `main_controller_sp.py` | **Pose + Traj 合并**，每个文件夹先 pose 后 traj |

实际生产使用「拆分版」（先全量跑 pose，再全量跑 traj），因为两阶段对显存/时间需求不同，
拆分后可分别调参与重跑。`run_gt.sh` 是早期合并版，便于小规模测试。

### `run_gt_pose.sh` 关键参数

```bash
INPUT_ROOT="/kpfs_dataset_ssd/render/segment_output"      # 输入：每个子文件夹一个工件
OUTPUT_ROOT="/kpfs_dataset/.../output_25"                 # 输出根目录
LOGGER_FOLDER=".../logger/pose_8_2_m25"                   # 各 slot 日志
REFERENCE_ROOT="/kpfs_dataset/.../output"                 # 可选：参考输出，用于过滤 seam
NUM_GPUS=8
PER_GPU_JOBS=2                                            # 每 GPU 并行 2 个子进程
POSE_TIMEOUT_MIN=3                                        # 单条 seam 超时 3 分钟
```

`REFERENCE_ROOT` 的用途：只处理「参考目录里已经有有效位姿解」的 seam，
用于在新参数下重跑一批已知有解的 seam（跳过此前确认无解的 seam）。

### `run_gt_traj.sh` 关键参数

```bash
INPUT_ROOT=".../segment_output"        # 仅用于完成后移动文件夹（当前代码已注释 move）
OUTPUT_ROOT=".../output"               # 必须含 pose_done 标记的文件夹
DONE_FOLDER_ROOT=".../done"            # 完成后移动目标（当前注释）
TRAJ_TIMEOUT_MIN=3
```

## 2. 输入数据组织

`INPUT_ROOT` 下每个子文件夹 = 一个工件，必须同时包含：

- **1 个 `.usd`**：工件网格（用于碰撞检测与遮挡 raycast）
- **若干个 `.pkl`**：每条焊缝一个，文件名（去后缀）即 seam 名（如 `seam_1.pkl`）
- 可选 `.ply`：工件点云（`pc_path`，Traj 阶段视野代价的可选输入）

controller 扫描时只看后缀，找到 pkl+usd 即通过（不加载内容），以应对 4000+ 文件夹的快速过滤。
缺 pkl → "跳过空文件夹"；缺 usd → "文件夹不完整"。

---

## 3. 调度器结构（以 `PoseGenerator` 为例）

`main_controller_sp_pose.py` 中的 `PoseGenerator.run()` 分四步：

### Step 1 — 扫描有效文件夹
遍历 `input_root`，保留同时含 `.pkl` 与 `.usd` 的文件夹。

### Step 2 — 预检查（断点续跑）
对每个文件夹检查 `output/<folder>/`：
- 存在 `pose_done` 标记 → 已完成，跳过；
- 存在 `pose/` 子目录但无标记 → 直接补建 `pose_done`，跳过；
- 否则加入 `folder_queue`。

### Step 3 — 子进程启动函数 `start_pose`
为一个文件夹拉起一个独立 Isaac Sim 子进程：

```python
env["CUDA_VISIBLE_DEVICES"] = str(gpu_id)        # 绑定 GPU
self._cleanup_shm()                              # 清理 /dev/shm 残留共享内存
cmd = ["/workspace/isaaclab/_isaac_sim/python.sh", "optimize_pose.py", "--headless",
       "--input_folder", ..., "--output_folder", ..., "--slot_id", str(slot_id), ...]
# 若配置了 reference_root，且 reference/<folder>/pose 存在，追加 --reference_folder
proc = subprocess.Popen(cmd, env=env, preexec_fn=os.setsid)   # 独立进程组，便于整组 kill
```

### Step 4 — 主调度循环
维护：
- `available_slots`：空闲槽位（共 `MAX_PARALLEL = NUM_GPUS × PER_GPU_JOBS` 个）
- `gpu_load[gpu_id]`：每 GPU 当前任务数（上限 `PER_GPU_JOBS`）
- `running_jobs`：`(proc, gpu_id, folder, slot_id, start_time)`

循环逻辑：
1. 只要有空闲槽位且有 GPU 未满载，就从队列取一个文件夹启动；
2. 对每个运行中的任务检查**超时**与**完成**；
3. `time.sleep(0.3)` 后继续。

> **为什么用子进程隔离？** Isaac Sim 的 `AppLauncher` 是进程全局单例，一个进程只能初始化一次仿真；
> 且每个（文件夹）跑完后必须彻底回收 GPU 显存。因此每个文件夹 = 一个独立短命子进程。

## 4. 超时与「卡住 seam」黑名单机制

某些 seam 几何病态会让 ES/STOMP 长时间不收敛，卡死整个 slot。机制如下：

1. **per-seam 心跳**：子进程在处理每条 seam 前，把 seam 名写入 `output/<folder>/.current_seam_pose`
   （Traj 为 `.current_seam_traj`）；每跳过/完成一条会重写该文件刷新 mtime。
2. **超时判定**：controller 用 `time.time() - mtime(marker)` 作为「当前 seam 已耗时」，
   超过 `POSE_TIMEOUT`（默认 3 分钟）即判超时。marker 尚未建立时退回到子进程启动时间。
3. **拉黑**：超时后 `_record_stuck_seam` 读取 marker 中的 seam 名，
   追加到黑名单文件（Pose：`input/<folder>/blacklist_pose.txt`；Traj：`output/<folder>/blacklist_traj.txt`），
   然后 `os.killpg(SIGKILL)` 杀掉整个进程组，释放槽位。
4. **重跑时跳过**：`optimize_pose.py` / `optimize_traj.py` 启动时读黑名单，跳过其中的 seam。
   这样重跑该文件夹时，卡住的 seam 被绕过，其余 seam 正常处理。

---

## 5. 完成判定：`.done` 哨兵 + SIGKILL

子进程经 `python.sh` 包装器启动，该包装器在收到 SIGKILL 时返回**非零退出码**，
无法用退出码区分「正常结束」与「被杀」。解决方案（见 `skip_strategy.md`）：

子进程在 `__main__` 末尾：
```python
opt.run()
open(os.path.join(output_folder, ".done"), "w").close()   # 正常完成写哨兵
os.kill(os.getpid(), signal.SIGKILL)                      # AppLauncher 无法安全退出，强制自杀
```

controller 判定表：

| 子进程 `ret` | `.done` 是否存在 | 结论 |
|-----|------|------|
| 0 | 任意 | 成功 |
| 非零 | 是 | 成功（SIGKILL 是预期收尾行为） |
| 非零 | 否 | 失败，下次重跑 |

成功后：Pose 阶段若 `pose/` 子目录存在 → 写 `pose_done`；Traj 阶段若 `traj/` 存在 → 写 `traj_done`。

## 6. 阶段衔接与文件夹移动

- **拆分版**：`run_gt_pose.sh` 跑完所有 pose（产出 `pose/` + `pose_done` + `path.json`）；
  之后 `run_gt_traj.sh` 扫描 `output_root` 中**带 `pose_done`** 的文件夹跑 traj。
  Traj 完整性判据：`traj/` 中的 seam 集合 ⊇ (`pose/` 的 seam 集合 − `blacklist_traj`)。
  完整即写 `traj_done`。（`try_finalize` 移动 input→done 的逻辑在当前 traj controller 中已注释。）
- **合并版** `main_controller_sp.py`：每个文件夹 pose 成功后，在**同一 slot/GPU** 立即链式启动 traj；
  traj 成功后 `shutil.move(input/<folder> → done_folder_root/<folder>)`，下次扫描自然不再出现。

---

## 7. 幂等性总结

| 场景 | 行为 |
|------|------|
| Pose 已完成、Traj 未完成 | 跳过 Pose，直接 Traj |
| Pose、Traj 都完成 | 两阶段均跳过 |
| `traj/` 存在但 `pose/` 缺失 | `optimize_traj.py` 直接 `rmtree(output/<folder>)`，下次全流程重跑 |
| 单条 seam 已有输出 pkl | 子进程内逐 seam 跳过（`if os.path.exists(out_file)`） |
| 中途崩溃无 `.done` | 视为失败，下次重跑该文件夹（已完成的 seam 仍跳过） |
| seam 反复超时 | 进黑名单，重跑时绕过 |

> **逐 seam 增量保存**：`optimize_pose.py` / `optimize_traj.py` 每完成一条 seam 立即 `pickle.dump`，
> 因此即使中途被杀，已算出的 seam 也已落盘，重跑只补未完成的。

## 8. 其它 controller 变体

- `main_controller.py`：单 GPU、顺序处理，逻辑最简，用于调试。
- `main_controller_sp_new.py`：在 `main_controller_sp.py` 基础上启用 **NVIDIA MPS**
  （Multi-Process Service，需 sudo），让同 GPU 上多进程更高效共享 SM。
- `run_gt_split.sh`：拆分跑法的便捷脚本。
