# 渲染整条采样后轨迹 —— 方案

## 目标

新增一个 Python 文件（建议 `render/render_trajectory.py`），**回放并渲染一整条关键帧下采样后的轨迹**：
机械臂沿 `(L,8)` 轨迹逐关键帧运动，每个关键帧渲染左右目 RGB + 深度。

- 输入 pkl：`scripts/traj_downsample.py` 的产物，如
  `/media/a/新加卷/tempt/5_ds/BEAM_1aEEYa00Ed5Z4sE34qDJKu_part_watertight_type2_seam0.pkl`
  （`Scene` pkl，内含 `sampled_trajectories`、工件、障碍、init pose、焊缝——渲染所需信息全在里面）。
- 输入 config：`configs/default.yaml`（相机内外参 + robot.usd_path + robot.cfg_path 的单一真源）。
- 输入输出目录：渲染结果落盘根目录。

## 与 `render/render_seam.py` 的本质差异

| | `render_seam.py`（现有） | `render_trajectory.py`（新增） |
|---|---|---|
| 机械臂关节角 | 恒为 `retract_config`（不动） | **逐关键帧变化**（取 `(L,8)` 前 6 列） |
| 工件位姿 | **逐候选 pose 变化**（并行轴） | **固定**（= 该轨迹 init pose 的 `workpiece_pose7`） |
| 障碍物 | 不 spawn | **spawn**（该 (seam,hand) 下的 `scene.obstacles`） |
| 并行轴 | 工件候选 pose | **轨迹关键帧** |
| 输入 | `.obj` + `seam_*.npy` | 下采样 `Scene` pkl |

一句话：把 render_seam「动工件、钉死机械臂」翻过来 → **「钉死工件+障碍、动机械臂」**，并行环境沿关键帧铺开。

## 关键洞察：渲染阶段不需要 curobo / warp

关节角已存在 `(L,8)` 里。Isaac Sim 把机械臂 Articulation 驱动到这些关节，相机作为 Link6 的子节点由
Isaac 直接算出世界位姿。所以渲染**只用 numpy 读 pkl + Isaac FK**，不碰 curobo/warp/CameraFKConfig，
也就**没有** `compute_goal_pose`/`plan_explore_path` 那种「污染 warp、须拆进程」的问题——单进程即可。

（相机外参仍来自 `configs/default.yaml` 的 `sensor.camera` / `sensor.camera_right`，与下采样 FK 用的
`CameraFKConfig`(mount_link=Link6 + 同一外参) 完全同源，故渲染出的左目位姿 = 采样时算的相机位姿。）

## 数据来源（从下采样 pkl 里取什么）

```python
scene = Scene.load(pkl)                      # 只需 numpy，可在 Isaac 进程内直接 load
# 选定一条轨迹 (sid, hand, index, j)：
arr = np.asarray(scene.sampled_trajectories[sid][(hand, index)][j], float)  # (L,8)
positions = arr[:, :6]        # (L,6) 关键帧关节角
observe    = arr[:, 6].astype(int)  # (L,) 该关键帧是否被相机拍过
goal       = arr[:, 7].astype(int)  # (L,) 该关键帧是否为段到达点

scene._set_cur_seam(sid)
scene.set_init_pose(hand, index)     # ← 设 scene.workpiece_pose（base 系 pose7，本轨迹固定工件位姿）
obstacles = scene.obstacles.get(sid, {}).get(hand, [])   # 本 (seam,hand) 的障碍
```

- 工件网格：`scene.workpiece_obj`（`_watertight.obj`；渲染优先找同目录 `_part.usd`，无则 OBJ→USD，
  沿用 render_seam 的 `asset_convert.convert_workpiece_obj` / scene_viz 的 usd 候选逻辑）。
- 障碍→几何：复用 `scene._obstacle_solid_trimeshes(hand)`（已把 Box/Tube prim + 棱柱/圆筒 mesh 统一成
  base 系实体 trimesh），逐个 spawn 成静态 `UsdGeom.Mesh`；或直接照搬 scene_viz.`show_scene_isaacsim`
  里的 `spawn_box_prim` / `spawn_mesh`。二者坐标系都在 base 系，与工件同框。

> 注意：`workpiece_pose7` 逐 init pose 不同，`obstacles` 逐 (seam,hand) 不同，所以**每换一条轨迹都要重建场景**
> （工件+障碍的摆放变了）。同一条轨迹内工件/障碍不动，只有机械臂关节变。

## CLI 设计（对齐 render_seam + show_trajectory_isaacsim）

```
--pkl           下采样 Scene pkl（必填）
--config        default.yaml（默认 configs/default.yaml）
--out           输出根目录（必填）
# 轨迹选择（不给 --all 时按下面单选一条，语义同 scene_viz.show_trajectory_isaacsim）
--seam-id       焊缝号（默认取 pkl 里第一条有采样结果的）
--hand          forehand / backhand（默认不限）
--traj-index    过滤后第几条（默认 -1=最新）
--all           渲染 pkl 内【全部】有采样结果的成功轨迹（批量；忽略上面单选）
# 渲染哪些关键帧
--observe-only  只渲染 observe==1 的关键帧（默认关：渲染全部 L 个关键帧=整条轨迹）
# 复用 render_seam 的通用项
--max-envs 8 --spacing 40 --settle-steps 12 --warehouse-usd <url> --force-convert --headless
```

## 渲染主流程

1. **启动前**（模块级，同 render_seam）：`AppLauncher` 必须先于 isaaclab/pxr import；`enable_cameras=True`。
2. **读 config**：`robot.usd_path`（人工 USD）、`robot.cfg_path`（取 joint_names，**不再需要 retract**，
   关节角来自轨迹）、`sensor.camera[_right]` 左右目内外参（`_load_cameras_from_config`）。
3. **Scene.load(pkl)** → 枚举待渲染轨迹列表（`--all` 全量 / 否则单选一条）。
4. **逐条轨迹**（每条重建场景，因工件/障碍不同）：
   - `set_init_pose` 拿 `workpiece_pose7`；取 `obstacles`、`(L,8)`。
   - 建场景（`build_scene`）：warehouse(floor，关碰撞) + robot(Articulation，固定底座、关重力) +
     workpiece(固定 pose7、纯视觉) + 各障碍(静态 Mesh) + 左右目 `TiledCamera`(挂 `Link6/camera_{left,right}`，
     外参取自 config)。工件/障碍随 env 偏移 `off` 平铺到各并行环境。
   - **离地抬升**：沿用 `compute_group_lift`（按固定工件 bbox + `ROBOT_Z_RANGE_EST` 估），每条轨迹算一次，
     把 warehouse 下移 `lift`（机械臂运动范围由 Z_RANGE_EST 兜底，够用；障碍若更低可后续把障碍 bbox 也纳入）。
   - 选帧：`rows = range(L)` 或 `np.nonzero(observe==1)[0]`（`--observe-only`）。
   - **按 `max_envs` 分批**，每批：给各 env 机械臂 `write_joint_state_to_sim(q_row)` +
     `set_joint_position_target` → step `settle_steps` 帧 → 读左右目 `rgb`/`depth`/`K` +
     相机/底座世界位姿（**工件、障碍全程不动**，只改关节）。
   - 逐帧落盘（见下）。写该轨迹 `_DONE_` 哨兵（断点续跑）。

> 与 render_seam 的 `render_batch` 相比：删掉「设工件位姿 / 绑材质」的 per-batch 逻辑（工件已在建场景时钉死），
> 改成 per-batch「设机械臂关节角」。相机读取、抬升、render_info 组装几乎照搬。

## 输出布局

```
<out>/<part_stem>/seam{sid}_{hand}{index}_traj{j}/
    left/   {k}_rgb.jpg  {k}_depth.exr ...  render_info.npy   # k=关键帧行号；render_info 含【全部帧】信息(按帧堆叠)
    right/  {k}_rgb.jpg  {k}_depth.exr ...  render_info.npy
    _traj_meta.npy                    # 轨迹级：(L,8) 原数组、observe/goal、workpiece_pose7、
                                      #        障碍摘要、seam/hand/index、joint_names、frame_indices 等
    _DONE_seam{sid}_{hand}{index}_traj{j}   # 完成哨兵
```

`render_info.npy`（每侧【一个】，含该侧全部帧，沿用 render_seam 的字段语义但按帧堆叠）：
- 逐帧堆叠（F=帧数）：`frame_indices`(F,)、`cam_pos_list`(F,3)、`cam_quat_list`(F,4)、`cam_intrinsic`(F,3,3)、
  `jointstates`(F,6)【本关键帧关节角，不再是 retract】、`observe`(F,)、`goal`(F,)、相机/底座世界位姿(F,·)、`z_lift`(F,)。
- 轨迹级常量：`traj_key`(seam,hand,index)、`sampled_len`(L)、左右目内外参、`joint_names`、`workpiece_pose7`、
  `seam_line_base`、`extrinsic_*`、`depth_type` 等——与 render_seam 完全同义、同源（读同一 yaml）。
- `--observe-only` 时帧号可能不连续，`frame_indices` 记录 {堆叠下标 → 关键帧行号} 映射。

## 代码复用策略

render_seam.py 在**模块 import 时**就跑 `AppLauncher`，无法被别的脚本安全 import。两个选择：

- **方案 B（推荐、低风险）**：新文件自包含，拷贝 render_seam 里这些纯函数
  （`_load_cameras_from_config`、`load_robot_cfg`、`set_prim_pose`、`compute_group_lift`、
  `make_camera_cfg`、`_render_info_for_side` 及其 pose7/quat 辅助）。数值真源仍是 `default.yaml`，
  拷函数不产生「相机参数分叉」（读的是同一 yaml）。
- 方案 A（可选清理）：把上述共用纯函数抽到 `render/render_common.py`，render_seam 与 render_trajectory 都 import。
  更 DRY，但要动 render_seam。可作为后续重构，不阻塞本功能。

## 环境与运行

- 环境：`env_isaaclab` + Isaac Sim（同 render_seam）。机械臂 USD 取 `robot.usd_path`。
- 无碰撞需求（纯视觉回放），机械臂关重力、工件/障碍关碰撞。
- 自检：`--headless` 只 spawn + 跑几帧即打印帧数并退出。
- 后续（非本次核心）：仿 `scripts/bash/v1/traj_downsample_batch.sh` 写多 GPU 批处理，对一个目录下所有
  下采样 pkl × 各轨迹并行渲染 + 断点续跑。
