# 渲染整条采样后轨迹 —— 方案

## 目标

新增一个 Python 文件（建议 `render/render_trajectory.py`），**回放并渲染一整条关键帧下采样后的轨迹**： 
机械臂沿 `(L,8)` 轨迹逐关键帧运动，每个关键帧渲染左右目 RGB + 深度。

- 输入 pkl：`scripts/traj_downsample.py` 的产物，如
  `/media/a/新加卷/tempt/5_ds/BEAM_1aEEYa00Ed5Z4sE34qDJKu_part_watertight_type2_seam0.pkl`
  （`Scene` pkl，内含 `sampled_trajectories`、工件、障碍、init pose、焊缝——渲染所需信息全在里面）。
- 输入 config：`configs/default.yaml`（相机内外参 + robot.usd_path + robot.cfg_path 的单一真源）。
- 输入输出目录：渲染结果落盘根目录。

## 与 `render/render_seam.py` 的本质差异

| | `render_seam.py`（现有） | `render_trajectory.py`（新增） |
|---|---|---|
| 机械臂关节角 | 恒为 `retract_config`（不动） | **逐关键帧变化**（取 `(L,8)` 前 6 列） |
| 工件位姿 | **逐候选 pose 变化**（并行轴） | **固定**（= 该轨迹 init pose 的 `workpiece_pose7`） |
| 障碍物 | 不 spawn | **spawn**（该 (seam,hand) 下的 `scene.obstacles`） |
| 并行轴 | 工件候选 pose | **轨迹关键帧** |
| 输入 | `.obj` + `seam_*.npy` | 下采样 `Scene` pkl |

一句话：把 render_seam「动工件、钉死机械臂」翻过来 → **「钉死工件+障碍、动机械臂」**，并行环境沿关键帧铺开。

## 关键洞察：渲染阶段不需要 curobo / warp

关节角已存在 `(L,8)` 里。Isaac Sim 把机械臂 Articulation 驱动到这些关节，相机作为 Link6 的子节点由
Isaac 直接算出世界位姿。所以渲染**只用 numpy 读 pkl + Isaac FK**，不碰 curobo/warp/CameraFKConfig，
也就**没有** `compute_goal_pose`/`plan_explore_path` 那种「污染 warp、须拆进程」的问题——单进程即可。

（相机外参仍来自 `configs/default.yaml` 的 `sensor.camera` / `sensor.camera_right`，与下采样 FK 用的
`CameraFKConfig`(mount_link=Link6 + 同一外参) 完全同源，故渲染出的左目位姿 = 采样时算的相机位姿。）

## 数据来源（从下采样 pkl 里取什么）

```python
scene = Scene.load(pkl)                      # 只需 numpy，可在 Isaac 进程内直接 load
# 选定一条轨迹 (sid, hand, index, j)：
arr = np.asarray(scene.sampled_trajectories[sid][(hand, index)][j], float)  # (L,8)
positions = arr[:, :6]        # (L,6) 关键帧关节角
observe    = arr[:, 6].astype(int)  # (L,) 该关键帧是否被相机拍过
goal       = arr[:, 7].astype(int)  # (L,) 该关键帧是否为段到达点

scene._set_cur_seam(sid)
scene.set_init_pose(hand, index)     # ← 设 scene.workpiece_pose（base 系 pose7，本轨迹固定工件位姿）
obstacles = scene.obstacles.get(sid, {}).get(hand, [])   # 本 (seam,hand) 的障碍
```

- 工件网格：`scene.workpiece_obj`（`_watertight.obj`；渲染优先找同目录 `_part.usd`，无则 OBJ→USD，
  沿用 render_seam 的 `asset_convert.convert_workpiece_obj` / scene_viz 的 usd 候选逻辑）。
- 障碍→几何：复用 `scene._obstacle_solid_trimeshes(hand)`（已把 Box/Tube prim + 棱柱/圆筒 mesh 统一成
  base 系实体 trimesh），逐个 spawn 成静态 `UsdGeom.Mesh`；或直接照搬 scene_viz.`show_scene_isaacsim`
  里的 `spawn_box_prim` / `spawn_mesh`。二者坐标系都在 base 系，与工件同框。

> 注意：`workpiece_pose7` 逐 init pose 不同，`obstacles` 逐 (seam,hand) 不同，所以**每换一条轨迹都要重建场景**
> （工件+障碍的摆放变了）。同一条轨迹内工件/障碍不动，只有机械臂关节变。

## 渲染主流程

1. **启动前**（模块级，同 render_seam）：`AppLauncher` 必须先于 isaaclab/pxr import；`enable_cameras=True`。
2. **读 config**：`robot.usd_path`（人工 USD）、`robot.cfg_path`（取 joint_names，**不再需要 retract**，
   关节角来自轨迹）、`sensor.camera[_right]` 左右目内外参（`_load_cameras_from_config`）。
3. **Scene.load(pkl)** → 枚举待渲染轨迹列表（`--all` 全量 / 否则单选一条）。
4. **逐条轨迹**（每条重建场景，因工件/障碍不同）：
   - `set_init_pose` 拿 `workpiece_pose7`；取 `obstacles`、`(L,8)`。
   - 建场景（`build_scene`）：warehouse(floor，关碰撞) + robot(Articulation，固定底座、关重力) +
     workpiece(固定 pose7、纯视觉) + 各障碍(静态 Mesh) + 左右目 `TiledCamera`(挂 `Link6/camera_{left,right}`，
     外参取自 config)。工件/障碍随 env 偏移 `off` 平铺到各并行环境。
   - **离地抬升**：沿用 `compute_group_lift`（按固定工件 bbox + `ROBOT_Z_RANGE_EST` 估），每条轨迹算一次，
     把 warehouse 下移 `lift`（机械臂运动范围由 Z_RANGE_EST 兜底，够用；障碍若更低可后续把障碍 bbox 也纳入）。
   - 选帧：`rows = range(L)` 或 `np.nonzero(observe==1)[0]`（`--observe-only`）。
   - **按 `max_envs` 分批**，每批：给各 env 机械臂 `write_joint_state_to_sim(q_row)` +
     `set_joint_position_target` → step `settle_steps` 帧 → 读左右目 `rgb`/`depth`/`K` +
     相机/底座世界位姿（**工件、障碍全程不动**，只改关节）。
   - 逐帧落盘（见下）。写该轨迹 `_DONE_` 哨兵（断点续跑）。

> 与 render_seam 的 `render_batch` 相比：删掉「设工件位姿 / 绑材质」的 per-batch 逻辑（工件已在建场景时钉死），
> 改成 per-batch「设机械臂关节角」。相机读取、抬升、render_info 组装几乎照搬。

## 输出布局

```
<out>/<part_stem>/seam{sid}_{hand}{index}_traj{j}/
    left/   {k}_rgb.jpg  {k}_depth.exr ...  render_info.npy   # k=关键帧行号；render_info 含【全部帧】信息(按帧堆叠)
    right/  {k}_rgb.jpg  {k}_depth.exr ...  render_info.npy
    _traj_meta.npy                    # 轨迹级：(L,8) 原数组、observe/goal、workpiece_pose7、
                                      #        障碍摘要、seam/hand/index、joint_names、frame_indices 等
    _DONE_seam{sid}_{hand}{index}_traj{j}   # 完成哨兵
```

`render_info.npy`（每侧【一个】，含该侧全部帧，沿用 render_seam 的字段语义但按帧堆叠）：
- 逐帧堆叠（F=帧数）：`frame_indices`(F,)、`cam_pos_list`(F,3)、`cam_quat_list`(F,4)、`cam_intrinsic`(F,3,3)、
  `jointstates`(F,6)【本关键帧关节角，不再是 retract】、`observe`(F,)、`goal`(F,)、相机/底座世界位姿(F,·)、`z_lift`(F,)。
- 轨迹级常量：`traj_key`(seam,hand,index)、`sampled_len`(L)、左右目内外参、`joint_names`、`workpiece_pose7`、
  `seam_line_base`、`extrinsic_*`、`depth_type` 等——与 render_seam 完全同义、同源（读同一 yaml）。
- `--observe-only` 时帧号可能不连续，`frame_indices` 记录 {堆叠下标 → 关键帧行号} 映射。

## 代码复用策略

render_seam.py 在**模块 import 时**就跑 `AppLauncher`，无法被别的脚本安全 import。两个选择：

- **方案 B（推荐、低风险）**：新文件自包含，拷贝 render_seam 里这些纯函数
  （`_load_cameras_from_config`、`load_robot_cfg`、`set_prim_pose`、`compute_group_lift`、
  `make_camera_cfg`、`_render_info_for_side` 及其 pose7/quat 辅助）。数值真源仍是 `default.yaml`，
  拷函数不产生「相机参数分叉」（读的是同一 yaml）。
- 方案 A（可选清理）：把上述共用纯函数抽到 `render/render_common.py`，render_seam 与 render_trajectory 都 import。
  更 DRY，但要动 render_seam。可作为后续重构，不阻塞本功能。

## 新增：2D 实例分割标签（instance segmentation）

在现有 RGB + 深度基础上，每帧再输出一张 **2D 实例分割图**：像素级标注该像素属于哪个物体
（工件 / 各障碍 / 机械臂 / 焊缝 / 背景），供 2D 感知训练用。与深度/RGB 完全同视角、同分辨率、逐帧对齐。
其中**焊缝(seam)**是特殊类别——只进分割、RGB/depth 里不可见，实现见下方「新增类别：焊缝」小节。

### 深度范围（先记录，与分割无关但常一起问）

本管线用 Isaac `TiledCamera` 渲染，深度类型 `distance_to_image_plane`（像平面 z 距离，米），
范围 = 相机 `clipping_range = [1e-5, 1e+3]` m（**不受** config `sensor.max_depth_m=3.0` 约束——那是
`self_raycast` 模式的截断，本渲染路径不走）。落盘为 EXR **16-bit half float**（1 m 处 ~0.5 mm 精度，
远处精度递减）；无几何命中的像素多为 `0`/`inf`。场景含仓库背景，远处像素可达数十米。

### 关键机制：Isaac 分割 annotator 需要「语义标签 + 分割数据类型」两件事

> **已实现**：采用 `instance_segmentation_fast`（实例级），机械臂标一个 id，id 图存 16-bit PNG，
> id→标签映射【逐帧各存一份】。以下三种 annotator 对比仅作背景记录。

1. **给 prim 打语义标签**（否则分割图全是背景）：
   - 工件 / 机械臂：走 IsaacLab 的 `UsdFileCfg`，加 `semantic_tags=[("class", "workpiece")]` /
     `[("class", "robot")]`（`build_scene` 里 spawn 工件、robot 处）。**机械臂整体一个 id**
     （挂 Link6，画面里常带前端）。
   - 障碍：`spawn_obstacle_mesh` 直接建裸 `UsdGeom.Mesh`，spawn 后用
     `isaacsim.core.utils.semantics.add_update_semantics(prim, "obstacle_{i}")` 逐障碍打**不同**标签
     （`obstacle_0`、`obstacle_1` …），实例级区分。
   - warehouse 背景：不打标签 → 分割图里落到背景（另有 BACKGROUND/UNLABELLED id）。

2. **相机加分割数据类型**：`make_camera_cfg` 的 `data_types` 里加分割 annotator。三选一：
   | 数据类型 | 语义 | 是否需要标签 | 适用 |
   |---|---|---|---|
   | `semantic_segmentation` | 按**类别**上色/编号（同类合并） | 需要 | 只分「工件/障碍/机械臂」类别 |
   | `instance_segmentation_fast` | 按**带语义的实例**分（每个打标签的 prim 子树一个 id） | 需要 | **推荐**：工件、每个障碍各一 id |
   | `instance_id_segmentation_fast` | 每个 prim 一个唯一 id（不管语义） | 不需要 | 最细，但会把机械臂拆成一堆 link |

   **推荐 `instance_segmentation_fast`** + 逐障碍不同标签：既分实例又可控粒度（机械臂整体一个 id，
   不被拆成各 link）。
   - IsaacLab `TiledCameraCfg` 默认会把分割**上色成 RGBA**；要拿到 `(H,W)` 的**整数 id 图**，需设
     `colorize_instance_segmentation=False`（对应 `colorize_semantic_segmentation` /
     `colorize_instance_id_segmentation`）。

### 读取与落盘

- **读**：`render_batch` 里除 `rgb`/`depth` 外再取
  `cam.data.output["instance_segmentation_fast"]`（`(N,H,W,1)` 整数 id 图）与
  `cam.data.info[env_idx]["instance_segmentation_fast"]["idToLabels"]`（`{id: 语义标签或 prim 路径}` 映射）。
- **id 图落盘**：`{k}_seg.png`，**16-bit 单通道灰度 PNG**（实例数远小于 65536，无损、比 npy 省空间；
  超 65535 会报错）。`store_seg` 先用 int64 校验范围再降到 uint16，避免 uint32→uint16 截断。
- **映射落盘**：`id→标签` 映射【逐帧各存一份】——因多帧分摊在**多个并行 env**里渲，Isaac 的实例 id
  可能逐 env 不同，逐帧存最稳（`render_info.seg_id_to_label_list`，list 长度 = F，与各帧
  `{k}_seg.png` 一一对应）＋轨迹级 `seg_type` 字段。落盘前把 Isaac 的 `idToLabels`（值形如
  `{"class":"workpiece"}` 或 prim 路径）规整成 `{int_id: "workpiece"|"obstacle_0"|...}`。

### 实例的表示（如何区分两个同类物体）

id 图是**单通道整数图**：同一实例所有像素同一整数，不同实例不同整数。两个都标 `workpiece` 的工件会拿到
**两个不同 id**（如 1、2），`idToLabels` 里两者都映射到 `workpiece`——**靠 id 数值区分实例，靠映射知道类别**。
（当前场景每条轨迹只有一个工件（单 mesh），多实例的真实来源是多个障碍 `obstacle_0/1/...`。）

### 需要改动的点（已实现）

| 位置（`render/render_trajectory.py`） | 改动 |
|---|---|
| `make_camera_cfg` | `data_types` 加 `"instance_segmentation_fast"`；`TiledCameraCfg` 加 `colorize_instance_segmentation=False`；新增模块常量 `SEG_KEY` |
| `build_scene`（spawn 工件 / robot） | `UsdFileCfg(..., semantic_tags=[("class","workpiece")/("class","robot")])` |
| `spawn_obstacle_mesh` | 加 `label` 参数，spawn 后 `add_update_semantics(prim, "obstacle_{i}")`（逐障碍不同）；`prepare_job` 传 `label=f"obstacle_{oi}"` |
| `render_batch` | 读左右目 `SEG_KEY` 输出 + `data.info` 的 `idToLabels`，经 `_seg_labels_from_info`/`_normalize_seg_labels` 规整后塞进 `out[env_idx]` |
| `frame_record_for_side` | 逐帧存 `seg_id_to_label` |
| `build_side_render_info` | 轨迹级加 `seg_type`；逐帧 `seg_id_to_label_list`（list 长度 F） |

| `render/depth_io.py` | 新增 `store_seg`（16-bit PNG，越界报错） |

### 已确认的决策

1. **粒度**：✅ 实例级 `instance_segmentation_fast`（每障碍一个 id）。
2. **机械臂**：✅ 标一个 id（`class=robot`，整体不拆 link）。
3. **id 图格式**：✅ 16-bit 单通道 PNG（`{k}_seg.png`）。
4. **映射存放**：✅ 只逐帧存（`render_info.seg_id_to_label_list`，长度 F）＋轨迹级 `seg_type`。

### 新增类别：焊缝（seam）——只进分割、RGB/depth 不可见

在 robot / workpiece / obstacle_* 之外再加一类 **`seam`（焊缝）**。硬约束：**焊缝只能出现在实例分割里，
「有焊缝」与「无焊缝」时的 RGB、depth 必须逐像素一致**。

**焊缝的几何表示**：焊缝本身是两面交线（`_seam_frame` 里 `p0→p1` 的直线折线，无宽度），分割相机只对
**有面积的 prim 子树**分配实例 id，纯线段渲不出来。故沿 base 系焊缝线 `job["seam_line_base"]` 生成一根
**半径 4mm 的实体管（tube）**（`_seam_tube_mesh`：逐折线点放一圈 `SEAM_TUBE_SIDES=8` 顶点、平行传输滚动
截面基避免拐弯扭转、相邻两圈连四边形侧面 + 两端封盖；双面渲染故不在意绕序）。管心落在焊缝线上（**先不沿
角平分线外移**）。半径可由 `--seam-radius` 覆盖。

**为何要「双 pass 渲染」（核心）**：Isaac 的 `rgb`、`depth`、`instance_segmentation_fast` 是**同一次
光线追踪**出的三张 AOV。一个 prim 要么被渲染（三张图都含它），要么设 `MakeInvisible()`（三张图都不含它，
**包括分割**）——**没有「只进 seg、不进 rgb/depth」的单-prim 开关**。所以焊缝管平时 `invisible`，`render_batch`
里每个 batch 渲**两遍**：

  1. **pass1（焊缝 invisible）** → 读 **RGB + depth**。此时场景=无焊缝（invisible prim 不参与光追），
     故 RGB/depth 与不加焊缝逐像素一致。读完立即把 RGB/depth 拷到 CPU（pass2 会覆写 `camera.output`），
     并算好相机内参 / 世界位姿（几何量，两 pass 相同）。
  2. **pass2（焊缝 visible）** → `_step(seam_settle_steps)` 后**只读 seg**（RGB/depth 丢弃）→ 再置回
     `invisible` 供下一 batch。焊缝在 seg 里正确遮挡工件像素、也被机械臂/障碍正确遮挡（3D 遮挡与厚度由
     渲染器精确处理）。`seam_settle_steps` 由 `--seam-settle-steps`（默认 4）控制，等可见性切换传导到 seg AOV。

**代价**：每 batch 多一个 seg-only 渲染 pass（约 +40~60% 渲染时间）。

**改动点**（`render/render_trajectory.py`）：

| 位置 | 改动 |

## 坑：每帧相机位姿被冻结（多帧点云对不齐）—— 已修

### 现象

用 `render/visualize_traj_pointcloud.py` 把一条轨迹的多帧深度反投影、融合到 base 系时，
**不同帧的点云对不齐**（工件/障碍散成一层层壳）。加不加 `--seg` 都错——因为 seg 只换颜色、
不改坐标，点的 xyz 只由 `depth + K + 相机位姿` 决定。

### 根因

`render_batch` 原先用 `TiledCamera.pos_w / quat_w_ros` 读相机世界位姿。**这两个值对「挂在关节体、
由物理驱动的相机」是陈旧的——冻结在初始 retract 姿态，机械臂动了也不变**：

- RTX **渲染**读的是 Fabric 里的活变换 → RGB/深度图正确反映每帧不同视角；
- 传感器 **pos_w/quat_w_ros** 读的是 USD/XformCache（物理写进 Fabric 未回写 USD）→ 位姿冻结。

于是 `render_info.cam_pos_list/cam_quat_list` 整条轨迹是**同一个常量**（可实测：`cam_pos` 各帧
min==max）。viz 用同一个错误位姿去反投影**不同视角**的深度，各帧自然散开。
> 判据：`jointstates` 逐帧在变、`{k}_rgb/depth` 逐帧在变，但 `cam_pos_list` 不变 → 命中此坑。

### 修法（方案 ③：Link6 活位姿 ∘ config extrinsic）

相机世界位姿 = **底座位姿 × [底座→Link6 的 FK] × [Link6→相机 的 extrinsic]**。三段里只有中间 FK 难，
**不自己重算 FK（那要把 curobo 接回渲染进程，违背设计），而是直接读 Isaac 已算好的 Link6 活位姿**：

- Link6 世界位姿取 `robot.data.body_link_pos_w/body_link_quat_w`（物理 tensor，逐帧真实更新，
  与坏掉的 `camera.pos_w` 是两个来源）；
- 乘 `configs/default.yaml` 的 extrinsic（与相机 spawn 用的 `OffsetCfg(convention="ros")` 同一份，
  故组合出的就是 ROS 光学相机帧，等价原 `quat_w_ros`）；
- 再喂现有 `_cam_pose_arm` 转成 base 系 + USD 光学存盘。**下游 `_cam_pose_arm`、viz、seg 全不改。**

为什么不用 ①标定法 / ②纯文件重算 FK：①对 extrinsic 约定过度谨慎、没必要；②要重实现 FK，且须与
Isaac 驱动机械臂的运动学逐关节完全一致，否则存的位姿和渲出的图对不上。③复用 Isaac 的 FK 最稳。

### 改动点（`render/render_trajectory.py`）

| 位置 | 改动 |
|---|---|
| `_link6_index(scene)` | 新增：在 `body_names` 里定位 Link6 下标 |
| `_cam_pose_w_from_link6(...)` | 新增：Link6 活位姿 ∘ extrinsic → 相机世界位姿(ROS) |
| `render_batch` | 删 `left.pos_w/quat_w_ros`，改逐 env 读 Link6 活位姿重建 `left_pos_w/left_quat_w/right_*` |

### 影响 / 验证

- **此坑修复前渲染的所有数据（`cam_pos_list` 冻结）作废，须重渲。**
- 开跑第一屏应见 `[sanity:left/right] ... OK`；若 `⚠` 则 extrinsic 约定/组合顺序有误，先排查再批量渲。
- 重渲后 `cam_pos_list` 应逐帧变化；viz（不带 `--seg`）多帧点云应对齐。
