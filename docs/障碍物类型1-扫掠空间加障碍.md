# 障碍物类型1：在已算轨迹的某 link 扫掠空间中加障碍（Scene.add_obstacle_type1）

> 状态：**计划文档，尚未改代码**。目标是给 `Scene` 增加 `add_obstacle_type1` 方法，
> 与已有的 `add_obstacle_type2` / `add_obstacle_type3` 并列（同样产出 `ObstacleSpec` 追加进
> `self.obstacles[seam_id]`，走同一条下游可视化 / 碰撞注入链路）。

## 1. 需求

针对某焊缝（例：焊缝 169）已经算好的一条观测轨迹
`scene.trajectories[169][('forehand', 0)]`，在**这条轨迹里某个 link 的扫掠空间**中放一个障碍物：

- 输入：用**哪条轨迹**（`seam_id` + 二级 key `(hand, index)`，必要时再指定 list 里第几段 entry）、
  用**哪个关节/link 的扫掠空间**（`Link1` / `Link2` / … / `xiaoyu_accessory_link`）。
- 约束①：障碍必须与该 link 的扫掠空间**有交集**（否则挡不住这条轨迹，没意义）。
- 约束②：障碍必须**完全落在 `init_free` 空间之外**。因为 `init_free` 是「假设无障碍」的起步引导
  空间，若障碍侵入其中会与「起步一定 FREE」的前提冲突。
- 产出：一个 `ObstacleSpec`（`otype=1`），追加进 `self.obstacles[seam_id]` 并返回，供后续
  可视化 / `compute_goal_pose` 碰撞注入 / `plan_explore_path` 真值世界使用。

## 2. 与旧 demo（launch.json: place_obstacles）的关键差异

旧 demo = `scripts/place_obstacles.py` + `gt_gen/obstacle_placement.py`，本次**复用其大部分几何逻辑**，
但有两处必须改：

| 维度 | 旧 demo | 本次 add_obstacle_type1 |
|---|---|---|
| 轨迹来源 | demo 内部用 curobo/stomp **现规划**一条 retract→goal 默认无障碍轨迹 | 直接取 `scene.trajectories[seam_id][(hand,index)]` 里**已算好**的 `positions` |
| init_free 空间 | `_clears_init_free` / `_signed_dist_cyl` 用**圆柱**（`init_free_cyl_radius/height`）——旧版本 | 现行 `init_free` 是 **box**（`method_for_init: "box"`，用 `box_min_m_for_init` / `box_max_m_for_init`）——必须按 box 排除 |
| 输出形态 | 每 link 产 1 个场景，做三条件验证（默认路径碰撞 / 有绕行解 / 绕行明显不同），存 npz | 只造 1 个障碍，产 `ObstacleSpec` 追加进 `self.obstacles`；**不做三条件验证、不重新规划** |
| 障碍数量 | 沿默认轨迹对多个 key_link 各产一场景 | 单次调用只放 1 个障碍（指定单一 link） |

> ⚠️ init_free 差异是本任务的核心。当前 `_fresh_explore_voxmap`（`scene.py:1244`）按
> `cfg.init_free_method_for_init` 选 box/cylinder，实际配置是 `box` + `box_min_m_for_init /
> box_max_m_for_init`。而 `obstacle_placement.place_in_corridor` 里写死用圆柱
> `_signed_dist_cyl` / `_clears_init_free`。若不改，排除的是**错误的（旧圆柱）init 空间**，
> 障碍可能落进真正的 box init_free 里。

## 3. 可复用的现成件（obstacle_placement.py）

- `compute_link_sweep(cfg, traj, links)` → `(per_wp, origin)`：
  - `per_wp[link]`：`(T, S, 4)` 每路点该 link 各碰撞球 `[x,y,z,r]`（base 系）。
  - `origin[link]`：`(T, 3)` 每路点该 link 原点位置（估切向用）。
  - **直接把已算轨迹的 `positions` (T,DOF) 当 `traj` 喂进去**即可，无需改动。
- `place_in_corridor(...)`：解析解——在时间窗内取「离 init 空间最深、离 goal 够远」的扫掠球心
  当障碍几何中心，构造性保证与扫掠并集有交、且整只在 init 空间外。**需要把它对 init 空间的
  依赖从「圆柱」参数化为「圆柱 or box」**（见 §5）。
- `_overlaps_sweep(prims, sph_link)`：精确「点-实体」判交，判障碍是否真嵌进扫掠管（约束①兜底）。
- `_shape_for` / `obstacles.build` / `ObstacleSpec`：造形状 + 原语（Box/Tube）+ 载荷封装。

## 4. 方法签名（拟）

```python
def add_obstacle_type1(self, link: str, *,
                       hand: str = None, index: int = None, entry_index: int = -1,
                       otype: str = None, size_scale: float = None,
                       angle_deg: float = None, thickness: float = None,
                       seed: int = 0, **overrides) -> ObstacleSpec:
    """在【当前焊缝已算轨迹】的指定 link 扫掠空间中放 1 个障碍（与扫掠有交、且在 init_free 外）。"""
```

- `link`：必填，扫掠空间取哪个 link（须在 yml `collision_spheres` 里有定义）。
- `hand` / `index`：定位轨迹二级 key `(hand, index)`；缺省用当前 init pose 的 key
  （`self._trajectory_key()`，`scene.py:708`）。
- `entry_index`：该 key 下 entry 列表里第几段（默认 `-1` 取最后合并/最新一条），取其 `positions`。
- `otype`：障碍具体类型（`obstacles.list_obstacles()` 之一，如 `plate`）；缺省从 config
  `obstacle_types` 取（空则随机抽一种，用 `seed+seam_id` 的 rng 复现）。
- `size_scale` / `angle_deg` / `thickness`：缺省从 `obstacle_placement.type1` 的区间用 rng 采样
  （`size_scale_range` / `angle_jitter_deg` / `thickness_range_m`），与 type2 的 `_resolve` 风格一致。

## 5. 算法步骤

1. **取轨迹**：`traj = self.trajectories[self.seam_id][(hand,index)][entry_index]["positions"]`
   （校验 key/entry 存在、`positions` 形状 `(T,DOF)`、`T>=3`）。
2. **算扫掠**：`per_wp, origin = compute_link_sweep(self.cfg, traj, [link])`；
   若 `link not in per_wp`（无碰撞球定义）→ 抛清晰错误。
3. **goal 位置**：取当前焊缝 goal 的位置分量（`self.goal_poses` 或 `_seam_frame` 的 mid），
   供 `goal_clearance_m` 用（障碍别贴焊缝）。
4. **放障碍**：调 `place_in_corridor(per_wp, origin, link, otype, size_scale=…, angle_deg=…,
   pos_frac=…, jitter_vec=…, thickness=…, cfg=self.cfg, goal_pos=…)`。
   - 返回 `(prims, anchor_eff, meta)` 或 `None`（该 link/类型在最深点都塞不进 init 外余量）。
   - `None` 时：可换随机 `otype` / `size_scale` 重试至 `max_attempts`，全失败则抛错说明「该 link
     扫掠空间几乎全在 init_free 内、放不下」。
5. **封装**：造 `ObstacleSpec(otype=1, kind=otype, prims=prims, seam_line=…, meta=meta)`，
   `self.obstacles.setdefault(self.seam_id, []).append(spec)`，返回 spec。

### 5.1 init_free 从圆柱改为 box（核心改动）

`place_in_corridor` 现在两处依赖圆柱：`_signed_dist_cyl`（步①选最深外部点）、`_clears_init_free`
（步④兜底）。改为按 `cfg.init_free_method_for_init` 分派：

- 新增 `_signed_dist_box(pts, cfg)`：点到轴对齐 box `[box_min_for_init, box_max_for_init]` 的
  **带符号距离**（外正内负），闭式向量化（与 `_signed_dist_cyl` 对称）：
  - 令 `d = max(lo - p, p - hi, 0)`（逐轴，box 外的溢出量），box 外 `sd = ‖d‖`；
  - box 内 `sd = max(lo - p, p - hi)` 的逐轴最大（负值，到最近面的距离）。
- 新增 `_clears_init_free_box(prims, cfg)`：逐 prim 用保守包围球 `(c, rb)` 判与 box 无交
  （`box` 各维膨胀 `rb` 后 `c` 是否在外），与 `_clears_init_free` 对称。
- `place_in_corridor` 内把 `_signed_dist_cyl(...)`→按 method 选 `_signed_dist_box` 或
  `_signed_dist_cyl`；`_clears_init_free(...)` 同理。默认 method 未配置时退回圆柱（保持旧 demo 行为）。

> 这样 `place_obstacles.py`（旧 demo）与新 `add_obstacle_type1` 共用同一份、可切换的 init 排除逻辑，
> 单一来源，避免两套 init 定义漂移。box 的角点从 `cfg.init_free_box_min_for_init /
> init_free_box_max_for_init` 读（`config.py:129/134`）。

### 5.2 下游集成：`_obstacle_solid_trimeshes` 需支持 otype==1

`_obstacle_solid_trimeshes`（`scene.py:547`）当前只认 `otype==2`（meshes）与 `otype==3 open_box`
（Box prims）。type1 产出的是 `obstacles.build` 的 **Box/Tube 原语**，需扩展：

- `otype==1`：遍历 `spec.prims`，`Box`→`_box_prim_to_trimesh`（已有）；`Tube`→新增一个
  `_tube_prim_to_trimesh`（trimesh 圆柱 + prim pose）。
- 这样 type1 障碍能自动进 `compute_goal_pose` 的碰撞世界与 `plan_explore_path` 真值世界，
  和 type2/3 一致，无需额外接线。

### 5.3 坐标系转换（实现时补充的正确性关键）

扫掠球（`compute_link_sweep` 的 FK）与 `init_free` box 都在 **base_link 系**，故放置在 base 系里完成；
但类型2/3 障碍是以 **工件 mesh 系** 存储（下游 `_build_explore_world` / `_inject_obstacles_into_*`
统一按当前 init pose 的 `workpiece_pose7` / `T_workpiece_in_base` 变到 base 系）。因此 type1 必须：

1. 在 base 系用 `place_in_corridor` 放好（得到 base 系原语）；
2. 用 `inv(T_workpiece_in_base)` 把原语 pose 转回工件 mesh 系再存进 `ObstacleSpec`
   （新增模块级 `_transform_prim`，刚体左乘、dims/radius/height 不变）；
3. 下游再乘回 `T` → 恰好落回 base 系的放置点。

`goal_clearance_m` 用 `cur_init_pose.seam_center_base`（base 系焊缝中心），与放置系一致。

> `obstacle_placement.py` 新增 `_signed_dist_box` / `_clears_init_free_box` +

## 7. 明确不做

- 不重新规划轨迹（复用 `scene.trajectories` 已有的）。
- 不做三条件验证（默认路径碰撞 / 绕行解 / 绕行差异）——那是旧 demo 的场景生成职责。
- 不写 npz——障碍以 `ObstacleSpec` 挂在 `Scene` 上，随 `scene.save/load` 一起走。
